# 第18课：把图书馆的大门放到 GitHub Pages

先打开 [公开网站](https://autumn-cyber-aka.github.io/ml-research-navigator/)。你看到的按钮和页面由 GitHub Pages 提供。

想象一座图书馆：前端是服务窗口，后端是管理员，数据库是保存记录的柜子。我们把窗口搬到了 GitHub Pages，管理员和柜子仍在原来的云端。于是换了网址，你的书单仍然能保存。

## 第一步：先用一次

1. 打开上面的网址，搜索一篇论文。样例论文都是虚构的，用来练习。
2. 点登录。网页会带你去原来的云端网站完成 ChatGPT 登录，然后自动回到 GitHub Pages。
3. 新建一个书单，加入论文，修改阅读进度。
4. 刷新网页，记录仍在。它们保存在云端数据库里。
5. 试试评分、评论、帖子、回复、点赞、排行榜和共同作者网络。功能没有删掉。
6. 想让别人看书单，主动开启公开；关闭公开后，别人就不能继续读取它。个人阅读进度始终是私人的。

当前标签页保存一张临时“通行证”，最长使用12小时；关闭标签页或过期后可能需要重新登录。书单不会因此消失。退出按钮会作废当前 Pages 通行证；原云端网站的登录状态单独管理。

## 第二步：找到三个盒子

|盒子|真实文件|负责什么|
|---|---|---|
|窗口|`web/app/navigator.tsx`|显示全部功能；两个网址共用这份界面|
|送信员|`web/static-client/client.ts`|把请求送到云端，附上登录通行证|
|管理员|`web/app/api/data/route.ts`、`web/lib/store.ts`|检查身份、权限和数据，再读写数据库|

GitHub Pages 只运行浏览器里的程序。它不能运行 Python、MySQL 或我们的云端 API。因此，“全功能”需要前后端一起工作。

## 第三步：跟着登录走

点击登录 → 浏览器记住一次性的秘密 → 去云端完成 ChatGPT 登录 → 带一次性号码回到 Pages → 用秘密换通行证 → 后续请求带通行证。

一次性号码两分钟过期，只能兑换一次。数据库保存通行证的哈希，好比保存指纹而不是原件。新增的 `pages_auth_codes` 和 `pages_sessions` 两张表只负责这座桥；原有13张业务表继续使用，云端现在共15张表。

## 第四步：自己部署时按顺序做

1. 保留可运行的 Sites 后端及 D1 数据库。不要删除旧迁移文件。
2. 如果换了账号或仓库，在 `web/lib/deployment.ts` 修改前端和后端网址，在 `web/vite.pages.config.ts` 修改仓库路径，在 `web/static-client/index.html` 同步资源路径和后端连接地址。
3. 在 `web` 文件夹运行 `pnpm install --frozen-lockfile`、`pnpm typecheck`、`pnpm test`、`pnpm build:pages`。最后生成 `pages-dist` 文件夹。
4. 先发布后端的新版本，让登录接口和两张新表生效。
5. 在 GitHub 仓库的 Settings → Pages 中选择 GitHub Actions。
6. 推送到 main。`.github/workflows/pages.yml` 会构建、上传、发布页面。Actions 中出现绿色成功后再打开网址。
7. 搜索论文、登录、保存书单、刷新、退出。页面能打开只是第一步，保存记录也要检查。

修改前端后推送 main 会自动更新 Pages；修改后端接口还需要重新发布 Sites。两边部署不是同一个按钮。

## 小任务和答案

问题：关掉浏览器，书单会被删除吗？

答案：不会。浏览器里的通行证可能消失，但书单在云端柜子里，重新登录还能取出来。

问题：为什么不能只留下 GitHub Pages？

答案：静态窗口自己不能保管所有用户的记录，也不能替管理员判断谁能修改哪个书单。
