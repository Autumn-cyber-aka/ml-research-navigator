**今天的目标：** 找到网页和代码，知道它们不是同一个东西。暂时不写程序。

## 1. 五个词，先认脸

|词|生活里的比喻|在这里是什么|
|---|---|---|
|文件|一张写了内容的纸|例如 `README.md`|
|文件夹|装纸的文件袋|例如 `navigator`|
|路径|找到那张纸的路线|例如 `navigator/templates/papers.html`|
|程序|按顺序写好的办事步骤|例如“查论文，再显示出来”|
|源码|人能阅读和修改的程序文字|仓库里的 Python、HTML 等文件|

`navigator/templates/papers.html` 的意思是：打开 navigator 文件夹 → 打开 templates 文件夹 → 找到 papers.html 文件。斜线 `/` 在这里用来分隔层级。

文件名最后面的部分叫扩展名，常常提示文件类型：

|结尾|主要用途|现在要不要细读|
|---|---|---|
|`.md`|说明书，GitHub 会排版给你看|先读教程|
|`.py`|Python 程序|从第4课开始|
|`.sql`|数据库建表或操作指令|从第2课开始|
|`.html`|网页内容与结构|从第6课开始|
|`.css`|网页颜色、间距、大小|先知道用途即可|
|`.yaml` / `.yml`|工具的配置说明|学会主流程后再看|

扩展名只是命名约定，不是给电脑施魔法。例如随便把照片改名为 `.py`，它也不会变成 Python 程序。

## 2. 浏览器、编辑器、终端，分别做什么？

**浏览器**用来看和使用网页。你现在看到论文列表的地方，就是浏览器。

**代码编辑器**用来读和修改源码。这里可以使用 VS Code。选择“File / 文件 → Open Folder / 打开文件夹”，选中里面有 `README.md`、`navigator` 和 `sql` 的那个项目文件夹。

**终端**用文字给电脑下指令。在 VS Code 中选“Terminal / 终端 → New Terminal / 新建终端”。下面出现的输入区域就是终端。输入一条命令，按回车执行。

不要把终端命令输入浏览器地址栏，也不要把网页地址当成 Python 代码。

## 3. 找到“项目根目录”

“根目录”在这里指项目最外面一层，就像这本书的封面所在位置，不是说整台电脑的最外层。

你应该看到：

```text
ml-research-navigator/
  README.md
  pyproject.toml
  navigator/
  sql/
  tests/
  docs/
```

当前工作区外层也可能叫 `ml-research-navigator`，所以名字重复时不要靠猜。**以能同时看到 README.md、navigator、sql 为准。** 外面的 `outputs` 是交付副本；学习修改时用真正项目目录，避免改了副本却发现网页没变化。

在 macOS 终端输入：

```bash
pwd
```

它问“我现在在哪个文件夹？”输出会因电脑而不同。

再输入：

```bash
ls
```

它问“这里有什么？”如果看到了上面的文件，位置就对了。

`cd 文件夹名称` 表示走进一个文件夹，`cd ..` 表示退到上一层。例如只有在当前目录确实包含项目子文件夹时，才输入 `cd ml-research-navigator`。不要盲目连续输入。

## 4. 已经能看到网页？跳过安装

当前本机预览地址是 `http://127.0.0.1:5055`。

- `http`：浏览器和服务器交流的一种方式。
- `127.0.0.1`：这台电脑自己。
- `5055`：一个端口，可以先想成这台电脑上某个服务的门牌号。

**网页能打开，就直接去第1课。** 第一次读项目不需要先重新安装或重新建表。

如果打不开，可能是网页服务器没启动，也可能是数据库没启动。网页服务器和数据库是两个不同程序。GitHub 页面能打开，并不说明本机这两个程序正在运行。

## 5. 换一台电脑从头启动怎么办？

项目提供 Docker 和原生 MySQL 两条路线。只选一条；初学者先按 [README 的 Docker 路线](../../README.md#quick-start-with-docker)。Docker 可以暂时理解为“按说明启动一套隔离的运行环境”，它本身不是数据库。

这条路线有前提：电脑已经安装并启动 Docker，且终端能运行 `python3` 和 `git`。先分别输入：

```bash
python3 --version
git --version
docker --version
docker compose version
```

每条都应显示版本。若出现 `command not found`，表示命令没找到；先解决这一条，再做后面步骤。不要为了消除报错删掉项目。这个教程不假设所有电脑已经装好了工具。

在准备存放新项目的文件夹执行以下命令。**已有项目就不要重复克隆。**

```bash
git clone https://github.com/Autumn-cyber-aka/ml-research-navigator.git
cd ml-research-navigator
python3 scripts/configure.py
docker compose up --build -d
```

逐条解释：

1. `git clone`：把 GitHub 上的项目复制到本地，并带上版本记录。
2. `cd`：走进刚复制的文件夹。
3. `configure.py`：生成仅供本地使用的随机密码与配置，保存在 `.env`。成功时只显示创建了文件，不显示密码。
4. `docker compose up`：按配置启动数据库和网站；`--build` 表示构建运行环境；`-d` 表示放到后台运行。

等待启动成功，再用浏览器打开 `http://127.0.0.1:5055`。首次启动会建立数据库并放入16篇虚构论文。没有默认用户，你需要自己注册。

`.env` 是私密配置本，不要上传或发给别人。若 configure 提示文件已存在，是在保护旧配置，**不需要删除它**。若提示端口5055被占用，先看看旧预览是否正在运行。

## 6. 今天可以先不看什么？

先不读 `uv.lock`、Dockerfile 和 GitHub workflow。它们分别帮助固定依赖版本、构建环境和自动检查。像学骑车不用先拆发动机一样，先理解应用的主流程。
