# 第17课：同一个图书馆，为什么有两种实现？

你可以把一个图书馆建在自己家里，也可以建在大家都能访问的地方。借书、写推荐、记录进度这些事情可以相同，但房子的建造材料不同。

[点击打开公开网站](https://ml-research-navigator.lyujianchen182.chatgpt.site)。

这个项目现在保留两套代码。**学习时先读 Python + MySQL 版；想直接体验功能，打开公开网站。** 两边的数据不互相同步。

## 一张对照表

|你想知道什么|原版：本地学习|线上版：Sites|
|---|---|---|
|网页入口|本机 `127.0.0.1:5055`|部署记录中的 HTTPS 网址|
|主要代码|`navigator/`|`web/app/` 和 `web/lib/`|
|接待请求的人|Python 写的 Flask|TypeScript 写的 Worker|
|保存登记册的地方|MySQL|Sites 提供的 D1|
|怎么登录|注册邮箱和项目密码|点 Sign in with ChatGPT|
|谁保管登录凭证|项目的认证代码|Sites 平台|
|哪里学事务和索引|第8—11课、MySQL测试和实验|本课了解实现差异，不套用原版实验成绩|

D1使用 SQLite 的数据库技术。它也有表、主键、外键和 SQL，但不是 MySQL。TypeScript 是给 JavaScript 加上类型检查的语言；浏览器和服务器上的代码都能使用它。现在不需要先学完这些语言才能体验网站。

## 先在网站上做这六件事

1. 不登录，搜索 `Tiny`，打开论文，查看作者关系图。目录中的论文和作者仍然是虚构教学资料。
2. 点 **Sign in with ChatGPT**。你不需要再给本项目设置密码。这里的账号和本地注册的账号是分开的。
3. 在侧栏打开个人资料，把默认显示名 `Reader` 改成你愿意公开的昵称。系统不会拿邮箱当评论署名。
4. 打开 **My reading lists**，创建私人书单；打开书单，在 **Add several papers** 输入 `1, 2, 2`。它应该只加入两篇。
5. 在论文详情页保存阅读状态、写评论或发起讨论。另一个登录用户可以点赞；自己不能给自己点赞。
6. 主动点 **Publish this list** 后，别人才能在 **Community lists** 看到它。再点 **Make private**，原分享链接就不能继续查看。个人阅读进度始终不公开。

评论和讨论是公开内容。不要把密码、邮箱或私人材料写进准备公开的文字里。排行榜默认需要至少两份真实用户评分；新网站出现空排行榜是正常的。

## 跟着一次“加论文”走

1. 浏览器里的表单由 [`web/app/navigator.tsx`](../../web/app/navigator.tsx) 显示。
2. 点击提交后，它把“书单编号、论文编号、看到的版本号”发给 `/api/data`。
3. [`web/app/api/data/route.ts`](../../web/app/api/data/route.ts) 检查请求来自本站，再向平台确认当前登录者。
4. [`web/lib/store.ts`](../../web/lib/store.ts) 检查书单是不是这个人的，并检查论文编号。
5. D1用 `batch` 把相关 SQL 作为一个整体执行，再返回结果。
6. 网页重新读取数据库，显示保存后的内容。

这里也不会相信浏览器自己说“我是8号用户”。是谁，必须由服务器认可的登录信息决定。

## 同一个难题，不同的处理方法

原版：拿到 MySQL 行锁，再修改，失败就回滚。

线上版：D1 不提供同样的 `SELECT ... FOR UPDATE` 用法。代码把“版本号还是不是我看到的那个”写进每条修改条件，相关语句放进原子的 `batch`。如果已经被别人改过，旧操作收到409，提醒重新加载。

想象两个人都拿着第3版书单。第一个人提交后变成第4版，第二个人的“仅在第3版时修改”条件就不满足。程序不会默默覆盖新内容。

**不要在面试里说线上 D1 用了 MySQL 行锁。** 你可以说：“我保留 MySQL 学习版，同时做了 D1 部署适配；两版分别用行锁和版本条件处理相同的并发问题。”前提是你能亲手解释对应代码。

## 表的数量为什么不同？

原版是15张表；线上版是13张。少掉的是原版自己管理的登录会话表、登录尝试记录表，因为线上登录交给平台处理。不是把书单或评论删掉了。

线上 `users` 表只保存平台提供的本站用户编号、公开昵称和创建时间，不保存应用密码或邮箱。两套数据库都只预置同一份虚构论文目录，不伪造用户评论、评分或热度。

## 测试应该怎么看？

- 原版有38项真实 MySQL 测试，见原版测试记录。
- 线上业务有14项独立 SQL/权限测试，见 [`web/evidence/store-tests.txt`](../../web/evidence/store-tests.txt)。它们使用隔离的 SQLite 测试适配器，检查唯一约束、权限、版本冲突等。
- 另外检查了实际本地 Worker + D1 模拟器的 HTTP 请求，包括登录、保存、公开、撤回及请求来源检查。
- “本地测试通过”和“公网部署成功”是两件事。公开部署结果单独记录在 [DEPLOYMENT.md](../DEPLOYMENT.md)。

小题：你在本机书单里加了一篇论文，为什么线上账号没变化？

答案：这两个版本使用不同的数据库，而且没有实现同步。不是数据丢失了。

小题：看到网站用 D1，就能把简历里的“MySQL索引实验”改成“D1索引实验”吗？

答案：不能。原实验在 MySQL 上运行，数据和结论只能说明那个实验。
