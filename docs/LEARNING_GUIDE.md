现在已经有完整实现。不要一次读全部代码：先跑起来，每次沿一个操作往下追。软件跑通不等于你已经会做；记录自己实际理解、修改和验证的内容。

## 第一步：先运行，不先背名词

按 README 的 Docker 路线或本地 MySQL 路线启动。浏览器打开 127.0.0.1:5055。安装方式选一种；不需要两种都学。当前项目没有 React、C++ 或训练代码。

输入 `Tiny` 搜索，点击论文，再点击作者。你看到的是数据库里的虚构记录。页面输入交给 Flask，Flask 用 SQL 找 MySQL，Jinja 把结果变成 HTML。

## 第二步：从三张表开始

`papers` 存论文，`authors` 存作者，`paper_authors` 记录谁写了哪篇。论文1有两个作者，所以关联表有两行。作者姓名不能当身份证：不同人可能同名。

先自己写下面这个需求的 SQL，再看 routes.py：列出2025年论文的标题、作者名和作者顺序，按论文编号和作者顺序排列。手算 fixture 的结果，再到 MySQL 执行。不要只截图，要说清每个 JOIN 用了哪个编号。

## 第三步：理解权限与事务

用户编号决定“当前是谁”，来自会话，不能相信网页发来的 user_id。列表编号只能告诉你是哪个列表，不能证明它属于你。

把一次批量加入想成“把三个东西一起装进箱子”：第三个不存在，就把已经装进去的两个拿出来。这个全部撤销是回滚；事务控制什么时候真正保存。两个人同时操作时，还需要锁和唯一键。

## 第四步：亲手改一点

建议按以下次序，每次只做一项：

1. 给论文详情增加一个已有字段的展示，检查转义。
2. 给搜索增加“结果总数”相关测试，而非复制实现逻辑。
3. 写一个空白评论被拒绝且数据库没变化的测试。
4. 手画 batch_add 成功与失败的执行顺序。
5. 解释为何第二次提交旧 version 得到409，而不是覆盖别人。
